# 🍽️ FoodFlow Backend
 
FoodFlow is a full-stack food ordering backend designed around a modern Spring Boot architecture.
 
The backend provides restaurant and food management, secure JWT authentication, AI-powered food search, order management, Razorpay payments, real-time WebSocket notifications, asynchronous RabbitMQ messaging, and Redis caching.
 
The project follows a traditional layered Spring Boot architecture and uses PostgreSQL/Supabase as the primary database.

### 📦 Order Management
 
FoodFlow supports complete order management.
 
#### Order creation
 
Customers can create orders containing multiple food items.
 
An order can contain food items from only one restaurant.
 
Example:
 
```json
{
  "restaurantId": 1,
  "items": [
    {
      "foodId": 4,
      "quantity": 2
    },
    {
      "foodId": 5,
      "quantity": 1
    }
  ]
}
```
 
#### 💰 Price Snapshotting
 
FoodFlow permanently stores the food price at the time an order is created.
 
For example:
 
```
Food price:
₹280
 
Customer orders:
Quantity = 2
 
priceAtOrderTime = ₹280
subtotal = ₹560
```
 
If the restaurant later changes the menu price:
 
```
New Food price = ₹350
 
The existing order remains:
 
priceAtOrderTime = ₹280
subtotal = ₹560
```
 
This prevents historical orders from being affected by future menu price changes.
 
#### 🔄 Order Status Lifecycle
 
Orders follow a strict state machine.
 
```
                 PENDING
                /       \
               /         \
              ▼           ▼
        ACCEPTED       REJECTED
            │
            ▼
        PREPARING
            │
            ▼
          READY
            │
            ▼
        COMPLETED
 
PENDING
   │
   ▼
CANCELLED
```
 
**Valid transitions**
 
```
PENDING → ACCEPTED
PENDING → REJECTED
PENDING → CANCELLED
 
ACCEPTED → PREPARING
 
PREPARING → READY
 
READY → COMPLETED
```
 
Invalid transitions are rejected with:
 
```
400 Bad Request
```

### 💳 Razorpay Payments
 
FoodFlow integrates Razorpay for online payment processing.
 
Payment creation is allowed only when:
 
```
Order.status == ACCEPTED
```
 
The payment amount is calculated entirely on the server:
 
```
Payment amount = Order.totalAmount
```
 
The client cannot override the payment amount.
 
#### 🔐 Razorpay Signature Verification
 
Payment verification uses:
 
```
HMAC-SHA256
```
 
The backend verifies:
 
```
razorpayOrderId
       +
"|"
       +
razorpayPaymentId
```
 
against the Razorpay signature using the server-side secret.
 
The Razorpay secret is never returned to the client.
 
#### 💰 Payment Lifecycle
 
```
ORDER
  │
  ▼
ACCEPTED
  │
  ▼
Create Razorpay Order
  │
  ▼
Customer Payment
  │
  ▼
Verify Signature
  │
  ├───────────────┐
  ▼               ▼
SUCCESS          FAILED
```
 
An order cannot move from:
 
```
ACCEPTED → PREPARING
```
 
until:
 
```
Payment.status == SUCCESS
```

### ⚡ Redis Caching
 
FoodFlow uses Redis to reduce repeated database queries and improve response time.
 
Cached resources include:
 
- restaurants
- foods
- restaurant-foods
#### Cache durations
 
```
restaurants      → 60 minutes
foods            → 60 minutes
restaurant-foods → 30 minutes
```
 
#### Cache Invalidation
 
Cache entries are automatically evicted when data changes.
 
For example:
 
```
Food PATCH
    │
    ▼
Database updated
    │
    ▼
Redis cache evicted
    │
    ▼
Next GET
    │
    ▼
Fresh database data
```
 
PostgreSQL remains the source of truth.

```bash

```
 
### 2. Configure environment variables
 
Set the required database, JWT, Razorpay, RabbitMQ, Redis, and AI service variables.
 
### 3. Start the AI service
 
The Python FastAPI service must be running separately.
 
Example:
 
```bash
uvicorn main:app --reload --port 8000
```
 
AI service:
 
```
http://localhost:8000
```
 
Swagger:
 
```
http://localhost:8000/docs
```
 
### 4. Start RabbitMQ
 
RabbitMQ must be running for asynchronous event processing.
 
Default port:
 
```
5672
```
 
### 5. Start Redis
 
Redis must be running for caching.
 
Default port:
 
```
6379
```
 
### 6. Start Spring Boot
 
Using Maven:
 
```bash
mvn spring-boot:run
```
 
Or:
 
```bash
mvn clean package
```
 
Then run the generated JAR:
 
```bash
java -jar target/foodflow-backend-0.0.1-SNAPSHOT.jar
```

## 📌 Important Design Decisions
 
**PostgreSQL is the source of truth**
 
Redis is used only as a cache.
 
**RabbitMQ and WebSocket are not duplicates**
 
RabbitMQ:
 
```
Backend → Backend
```
 
WebSocket:
 
```
Backend → Client
```
 
**Payment amount is server-controlled**
 
The client cannot determine the amount sent to Razorpay.
 
**Order prices are immutable snapshots**
 
Changing a menu price does not change historical orders.
 
**JWT determines ownership**
 
The client does not manually specify the authenticated user when creating protected resources.
 
**PATCH is used for partial updates**
 
PATCH supports:
 
- 1 field
- 2 fields
- multiple fields
- all editable fields
while rejecting an empty update payload.
